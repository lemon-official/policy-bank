## Rules

1. **UX-1 Accessibility.** WCAG 2.2 AA for every new or changed screen.
2. **UX-2 Components.** Use design-system components; a new component needs design review.
3. **UX-3 Errors.** Every error state tells the user what happened and what to do next.
4. **UX-4 Localisation.** No hard-coded user-facing strings.

## How to apply

- In a spec, describe each changed flow and the states it has (empty, loading, error, success).
- Conflicts go in "Flagged concerns" with `policy_owner: design`.
